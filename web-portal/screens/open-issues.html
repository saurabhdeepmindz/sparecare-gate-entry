Open issues on Screens 1 to 3

Eight of the FRD's open items bear directly on these three screens. Four are High priority, and each one is a place where the specification records the behaviour as undecided rather than defined. The wireframes mark them with amber callouts; they should be settled before build rather than resolved by whoever writes the code first.

Decisions taken in these wireframes

Three things were designed rather than specified, and are flagged here so they can be accepted or overturned. The dashboard is treated as a landing screen, not a step — FR-003 describes it as the view a supervisor keeps open through the day, so work is launched from it rather than ending there. Gate entry is drawn as a two-step task with the Gate Entry Number pinned above the form once issued, following §4.6 and FR-001.1. The web portal shell — sidebar, page header, table conventions — is a design decision, since no existing SpareCare web portal was supplied to match.

Fields added beyond the source artwork

Three fields appear on Screen 1 that are not in the FRD's own wireframe images, because the Session 07 amendments require them and post-date that artwork. Date & Time of Receipt (FR-001.9, .10) — mandatory, system-captured, not configurable, and shown read-only precisely because §4.4 notes it must not look like an input that can be left blank. Nature of Inward Transaction (FR-001.11 with FR-030.1) — six values, chosen at the gate because it determines ownership and whether a payment is due. No. of Boxes (FR-001.12 with FR-001.21) — carried with an explicit indicative-only hint. The aging bucket filter on Screen 3 is likewise new: FR-003.6 and FR-003.7 require it and the artwork has no time dimension at all.
